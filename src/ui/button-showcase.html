Expert App - Professional Button System

🎨 Button Variants

Our professional button system provides semantic variants with consistent styling.

Usage:

.button .button-primary - Main actions (Generate, Save, Create)

.button .button-secondary - Supporting actions (Cancel, Settings)

.button .button-success - Positive actions (Add, Import, Confirm)

.button .button-danger - Destructive actions (Delete, Remove)

.button .button-warning - Caution actions (Reset, Warning operations)

📏 Button Sizes

Three size variants for different contexts.

Usage:

.button-sm - Compact spaces, utility actions

(default) - Standard interface elements

.button-lg - Important actions, modal buttons

🔘 Icon Buttons

Square buttons for icon-only actions.

Usage:

.button-icon - Square aspect ratio for icons

Combine with size modifiers: .button-icon.button-sm

👻 Ghost & Specialized Buttons

Minimal styling for subtle actions.

Usage:

.button-ghost - Minimal visual weight

.close-btn - Modal/dialog close buttons

.info-button - Help/information triggers

.version-nav-btn - Navigation controls

🔄 Button States

Interactive states and loading indicators.

States:

:hover - Elevated with subtle animation

:disabled - Grayed out, not interactive

.loading - Shows spinner, disables interaction

💡 Usage Guidelines

✅ Do:

  • Use semantic variants that match the action's intent
  • Add meaningful icons to improve recognition
  • Use consistent sizing within the same context
  • Leverage the loading state for async operations
  • Group related actions logically

❌ Don't:

  • Mix multiple primary buttons in the same group
  • Use danger styling for non-destructive actions
  • Override button colors with inline styles
  • Use icons without clear meaning
  • Ignore disabled states for unavailable actions
